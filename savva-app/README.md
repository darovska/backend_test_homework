# Семейный дневник Саввы — GitHub + Render + PostgreSQL

Сайт на Render, код на GitHub. Все записи будут храниться в частной PostgreSQL, доступ к данным — только после входа по семейному паролю. Google OAuth и синхронизация с таблицей полностью отсутствуют. После одноразового импорта единственный рабочий источник — PostgreSQL.

## Готовое приложение

- `server.py`: FastAPI, защита паролем (scrypt), HTTP-only подписанный сеанс, проверка источника и CSRF, защита от перебора, безопасное изменение общей JSON-записи в PostgreSQL.
- `site/index.html`: календарь с полями посещения, длительности, категорий, заметок, новых занятий, прогулок, досуга, часов логопеда.
- `site/sync.js`: вход, автоматическое сохранение, обновление данных, обработка конфликтов и копирование ссылки.
- `requirements.txt`: зависимости Python на Render.
- Данные из Google Sheets **не входят** в репозиторий. Первоначальный архив на 1678 занятий в 12 месяцах загружается из **приватной переменной окружения** Render `INITIAL_SNAPSHOT_GZIP_B64`, только если база пуста.

## Render

Новый web-service разворачивается с ветки `savva-family-dashboard`, рабочая папка `savva-app` в репозитории `darovska/backend_test_homework`.

- Runtime Python
- Build: `pip install -r savva-app/requirements.txt`
- Start: `cd savva-app && uvicorn server:app --host 0.0.0.0 --port $PORT`

Переменные окружения:

- `PUBLIC_BASE_URL`: точный адрес веб-сервиса, например `https://savva-family-live.onrender.com`
- `EDITOR_PASSWORD_HASH`: scrypt-хеш семейного пароля, не сам пароль
- `SESSION_SIGNING_KEY`: случайный ключ для подписанных cookie-сессий
- `INITIAL_SNAPSHOT_GZIP_B64`: приватная сжатая копия исходных данных, удаляется из env после успешного первичного импорта
- `DATABASE_URL`: **Internal Database URL** из Render Postgres (в Render → Database → Connect). Эта переменная обязательна для чтения и записи данных. Не передавай ее в GitHub или публичный чат.

При создании PostgreSQL на бесплатном тарифе обязательно следи за сроком истечения; он временный. Для долгосрочного хранения перейди на оплачиваемый Postgres и сделай резервный экспорт базы.

## Совместное использование

1. Открыть постоянную ссылку на дашборд.
2. Ввести семейный пароль. Передавать пароль отдельно от ссылки и только доверенным участникам.
3. В календаре выбрать день и менять минуты, посещение, заметки, добавлять и удалять занятия. Все изменения сохраняются в PostgreSQL и доступны другим участникам.
4. Зеленая надпись «Сохранено для всех» означает, что сервер подтвердил запись. В случае ошибки изменения сохраняются в текущей странице, нужно использовать «Повторить сохранение».
5. Если два человека одновременно редактируют **один день**, более позднему придет предупреждение; чужие изменения не перезаписываются. Изменения разных дней объединяются автоматически.
6. Раз в минуту при отсутствии несохраненных изменений сайт обновляет показания.

## Безопасность

- Репозиторий может быть публичным, но приватных детских данных и паролей в нем нет.
- Сервер не раскрывает дневник без сеанса.
- Все изменения требуют CSRF-подтверждения и подходящего Origin.
- Пароль не лежит в браузерном JS. В серверных настройках находится только scrypt-хеш.
- Для настоящей безопасности желательно использовать отдельные учетные записи с отзывом доступа; общая парольная схема проще, но пароль придется менять всем, если он утечет.
- Нельзя публиковать в GitHub `DATABASE_URL`, пароль, ключ подписи сеанса или файл экспорта JSON.
