# Google Play — подключение магазина, рекламных бонусов и выпуск

## Что уже реализовано в коде

В Android-проект вставляется собственный Java-плагин `ShelterBillingPlugin` на **Google Play Billing Library 9.1.0**:

- Получение **реальных локализованных цен** из Google Play через `queryProductDetailsAsync`.
- Запуск защищённого окна оплаты через `launchBillingFlow`.
- Получение токена и статуса покупки (`PURCHASED`, `PENDING`), без выдачи за незавершённую транзакцию.
- Восстановление активных покупок через `queryPurchasesAsync`.
- `consumeAsync` для расходуемых и `acknowledgePurchase` для постоянных продуктов **после подтверждения и сохранения награды**.
- Локальная защита от повторной выдачи по токену; для релиза нужна также серверная идемпотентность.
- Платный каталог не появляется в веб-версии, iOS и Яндекс Играх.

## Как собрать Android-проект

1. Установите Node.js 22+, Java 21, Android Studio/SDK.
2. Перейдите в папку `mobile` и выполните `npm install`.
3. Выполните `npm run android:create`, затем `npm run android:open`.
4. Убедитесь, что в `android/app/build.gradle` добавлено `com.android.billingclient:billing:9.1.0`, в AndroidManifest.xml — разрешение `com.android.vending.BILLING`, а `MainActivity.java` регистрирует `ShelterBillingPlugin`.
5. Проверьте Android `applicationId` и target SDK в настройках Gradle; используйте тот же пакет в Play Console.
6. Соберите подписанный AAB для внутреннего тестирования и загрузите через Google Play Console → **Testing → Internal testing**.

## Настройка Google Play Console

1. Создайте приложение с package name `com.kindhands.catshelter` (или измените ID в проекте и консоли одновременно).
2. В **Monetize → Products → One-time products** создайте четыре продукта с ID из `SHOP_ECONOMY_RU.md`, вариантом покупки и опубликованными ценами для нужных стран. Для упрощения примера нужен один базовый вариант покупки/одно доступное предложение на SKU.
3. Отметьте расходуемые (`shelter_supply_box`, `shelter_beds_3`, `shelter_rescue_box`) и постоянный (`shelter_groomer_kit`) на уровне *логики* игры; в Play Console тип one-time, фактическое `consume` или `acknowledge` определяет возможность повторной покупки.
4. Добавьте тестовые аккаунты в **License testing** и internal testing. Тестируйте покупку, отмену, состояние pending, отсутствие сети, восстановление, повторный запуск и отменённые/возвращённые покупки.
5. Цены, налоги и валюта берутся из Google Play, поэтому не указывайте неподтверждённые рублёвые или долларовые суммы в игровой HTML.

## Серверная проверка обязательна перед реальными платежами

Сейчас **по умолчанию покупки за реальные деньги заблокированы**. Вариант для разработчиков позволяет протестировать только лицензионные тестовые транзакции, но не предназначен для публичной продажи.

Рекомендуемый продакшен-поток:

1. Игра получает от Play SDK `productId`, `purchaseToken` и статус `PURCHASED`.
2. Авторизованный игрок отправляет токен на **ваш HTTPS backend**, а не напрямую в Google API из браузера.
3. Backend проверяет через **Google Play Developer API** `purchases.productsv2.getproductpurchasev2`: пакет приложения, продукт, статус оплаченной покупки и корректность токена. Сохраняет серверную уникальную пару (purchaseToken, учётная запись), выдаёт entitlement один раз и позволяет безопасно повторять проверку того же токена.
4. Клиент получает `{ "verified": true }` только после успешной проверки для своего пользователя и сохраняет права на покупку. Сервер должен возвращать тот же результат при повторном запросе по уже подтверждённому токену этого пользователя.
5. Только затем вызовом `finish` расходуемая покупка помечается consumed, а постоянная acknowledged. Подтверждение в установленный Play срок обязательно, иначе покупка может быть отменена/возвращена.
6. Для многодевайсного использования храните остатки платных расходников **на сервере**, синхронизируйте их с игровым профилем. Для списаний, возвратов и отзыва прав подключите Voided Purchases API и Real-time Developer Notifications (RTDN).

Настройка в Vite перед релизной сборкой (`mobile/.env.production`):

```ini
VITE_PLAY_VERIFY_URL=https://your-own-domain.example/api/google-play/verify
VITE_LOCAL_IAP_TEST=false
```

Ожидается POST JSON с `productId`, `token`, `platform`. Можно подключить Bearer token от собственной авторизации через `window.ShelterPlayerAuth.token` (реализовать авторизацию отдельно). Backend обязан самостоятельно проверить токен у Google и пользователя: **возвращать true без серверной проверки запрещено для релизной конфигурации**.

Локальный режим для **внутреннего тестирования** — `mobile/.env.local`:

```ini
VITE_LOCAL_IAP_TEST=true
```

**НИКОГДА** не выкладывайте сборку с этим параметром в production: выдача будет осуществляться без независимой проверки чека. Не используйте для тестовых сценариев личные реальные платежи, пока серверная проверка не готова. По возможности сначала создайте backend и тестируйте уже через него.

## Реклама AdMob

В `mobile/src/ad-bridge.js` используются **только тестовые** ID AdMob. До публикации замените application ID и рекламные block ID отдельно для Android/iOS, выключите режим тестирования, настройте UMP/GDPR и необходимые разрешения/публикации. Reward выдаётся только по результату успешного просмотра; при закрытии без награды — ничего. Не выдавайте бонус до `onRewarded`.

## Публикация и декларации

- Добавьте иконку, скриншоты и описание. Укажите **внутриигровые покупки** и **рекламу** в карточке Google Play.
- Отдельно предоставьте privacy policy и заполните Data safety. Учитывайте данные рекламной сети и ID устройств.
- Заполните content rating и целевую аудиторию. Если игра ориентирована на детей, отдельно проверьте Families Ads и связанные правила.
- Протестируйте изменение языка/масштаба, 360–480 px и крупные экраны, паузу, возобновление, отсутствие интернета, отказ в consent.
- Сделайте тестовую AAB-сборку, проведите internal testing, затем closed/open testing по необходимости и только после этого production.

Полезные первоисточники: https://developer.android.com/google/play/billing/integrate , https://developer.android.com/google/play/billing/lifecycle/one-time , https://support.google.com/googleplay/android-developer/answer/9858738 .
